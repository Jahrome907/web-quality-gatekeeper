02 / Use it

Two supported paths, stated plainly.

Use the published major Action tag for a repository workflow. Use a source checkout for local CLI evaluation. Both paths emit the same core artifact set.

Published path

GitHub Action

Pin the stable major tag, provide a public target, and upload outputs only when the run is not sensitive. 

jobs:
  web-quality:
    runs-on: ubuntu-latest
    env:
      WQG_SENSITIVE_AUDIT: "false"
      WQG_ALLOW_SENSITIVE_OUTPUTS: "false"
    steps:
      - uses: actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3
        with:
          persist-credentials: false
      - id: wqg
        uses: Jahrome907/web-quality-gatekeeper@v3
        with:
          url: https://your-site.example
          baseline-dir: .github/web-quality/baselines
      - name: Upload artifacts
        if: always() && (steps.wqg.outputs.sensitive-audit != 'true' || env.WQG_ALLOW_SENSITIVE_OUTPUTS == 'true')
        uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
        with:
          name: wqg-artifacts
          path: |
            ${{ steps.wqg.outputs.summary-path }}
            ${{ steps.wqg.outputs.summary-v2-path }}
            ${{ steps.wqg.outputs.report-path }}
            ${{ steps.wqg.outputs.action-plan-path }}
            ${{ steps.wqg.outputs.pr-risk-ledger-path }}
            ${{ steps.wqg.outputs.pr-risk-ledger-md-path }}
          if-no-files-found: warn

Source path

Local CLI

Build the current checkout with Node 22.19 or later, install Chromium, and invoke the compiled CLI directly. 

git clone https://github.com/Jahrome907/web-quality-gatekeeper.git
cd web-quality-gatekeeper
npm run engines:check
npm ci
npx playwright install chromium
npm run build
node dist/cli.js audit https://your-site.example --policy marketing

Registry status: web-quality-gatekeeper is not published on npm. Do not use npm install web-quality-gatekeeper or npx wqg as an installation path unless a future release explicitly adds registry publication.

04 / Boundaries

Know what the gate sees and what it can expose.

Browser evidence can contain page content, request failures, console output, and screenshots. Treat authentication and artifact publication as separate decisions.

Target and network boundary

  • Internal and private targets are blocked by default in CI and authenticated runs.
  • Requested targets, redirect destinations, browser requests, and Lighthouse's final URL are checked in sensitive mode.
  • Local unauthenticated development runs warn on internal targets; they do not silently turn them into public-safe evidence.

Credentials and output boundary

  • Headers, cookies, internal-target overrides, or WQG_SENSITIVE_AUDIT=true mark a run as sensitive.
  • Sensitive runs suppress artifact uploads and pull-request comments by default.
  • Reports and screenshots may contain audited page content. Set WQG_ALLOW_SENSITIVE_OUTPUTS=true only when publication is intentional.
