# v5 migration

Version 5 removes the optional native Rust visual-diff engine. Default pixelmatch
configurations need no change. The CLI flags, Action inputs and outputs, and report
schema versions are unchanged; historical reports recording `native-rust` remain readable.

The npm `@^5` and Action `@v5` references require publication of 5.0.0. Check
[Releases](https://github.com/Jahrome907/web-quality-gatekeeper/releases) and
[npm](https://www.npmjs.com/package/web-quality-gatekeeper) before updating a workflow.
Published 4.x tags remain unchanged.

## Remove native settings

- Remove `visual.engine` (or set it to `pixelmatch`) and remove `visual.nativeBinaryPath`.
- Unset `WQG_VISUAL_DIFF_ENGINE` if it selects `native-rust` or `native-rust-spike`.
- Remove `WQG_VISUAL_DIFF_NATIVE_BIN`, `WQG_VISUAL_DIFF_NATIVE_TIMEOUT_MS`, `WQG_ALLOW_NATIVE_VISUAL_ENGINE`, and `WQG_ALLOW_SCRIPT_NATIVE_ENGINE` from your environment and workflows.
- Run an audit against your existing baselines and review changed comparison results. Do not regenerate baselines merely to make a failure pass.

Legacy native selections fail with migration guidance rather than silently switching
engines. The [measurements](../engineering/VISUAL_DIFF_BENCHMARK.md) explain the removal.

When upgrading from v3, first follow the [v4 migration guide](v4.md) for explicit
visual baselines and output-directory ownership.
